────────────────────────────────────────────────────────────────────
一、横向溢出（U13 的窄视口验收项）
────────────────────────────────────────────────────────────────────

  desktop 1440x900   scrollWidth=1440  clientWidth=1440  → 无溢出
  narrow  375x812    scrollWidth=375   clientWidth=375   → 无溢出

  固件里刻意放了长引用路径（fastapi/dependencies/utils.py:511-604）与长仓库标识。
  引用容器自身可横向滚动（.citation 的 overflow-x: auto），但页面本身不溢出。

  实现要点：网格子项用 min-width: 0。不加这一条，长路径会把 grid 列撑开，
  375px 下页面整体横向滚动 —— 这正是计划要求避免的「撑破布局」。

────────────────────────────────────────────────────────────────────
二、完成态三区块共存（改版的硬约束）
────────────────────────────────────────────────────────────────────

  desktop 完成态 h2：架构报告 / 代码评审 / 代码问答
  narrow  完成态 h2：架构报告 / 代码评审 / 代码问答

  侧栏导航点「评审」后三个标题仍全部在 DOM。这条是改版方案的决定性约束：
  若侧栏做成视图切换，任一时刻只有一个区块存在，现有 40 个组件行为测试里
  报告/评审/问答三组会同时失败（它们在同一个完成态下各自 await 自己的标题）。
  锚点滚动同时满足工作台观感与 plan 的「单页应用，无路由」。

────────────────────────────────────────────────────────────────────
三、播报角色数量未增加
────────────────────────────────────────────────────────────────────

  desktop role 计数：status=0  alert=0
  narrow  role 计数：status=0  alert=0

  （完成态下进度区已卸载，故 status=0 符合预期。）
  新增的统计区不挂 role="status" / role="alert" / aria-live —— 现有测试用单数查询
  getByRole('status') 与 findByRole('alert') 取进度状态与错误提示，再加同名 role
  会让那些查询变成多匹配。统计是静态派生值，本身也不需要播报。
