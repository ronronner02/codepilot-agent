问：FastAPI 应用是怎么生成 OpenAPI schema 的
  预期找到 / 实际找到 -> 符合预期
  LLM 调用 1 次，检索 12 片段，最近距离 0.1508

  答：基于fastapi/applications.py:1070-1103 可以说明 FastAPI 生成 OpenAPI schema 的机制：

1. **入口方法**：`FastAPI.openapi()` 方法负责生成 OpenAPI schema，FastAPI 内部会调用此方法（fastapi/applications.py:1070-1103）。

2. **缓存机制**：该方法会先检查 `self.openapi_schema` 是否已存在，以及路由版本 `self._openapi_routes_version` 是否与当前 `self.router._get_routes_version()` 一致。如果 schema 已生成且路由版本未变化，直接返回缓存的 `self.openapi_schema`，避免重复生成的开销（fastapi/applications.py:1070-1103）。

3. **实际生成**：如果 schema 不存在或路由版本变化，则调用 `get_openapi()` 函数生成新的 schema，传入的参数包括：
   - `title`、`version`、`openapi_version`、`summary`、`description`
   - `terms_of_service`、`contact`、`license_info`
   - `routes`（应用的路由列表）、`webhooks`（webhook 路由）
   - `tags`（`openapi_tags`）、`servers`
   - `separate_input_output_schemas`
   - `external_docs`（`openapi_external_docs`）
   
   生成后将结果存入 `self.openapi_schema`，并更新 `self._openapi_routes_version` 为当前路由版本（fastapi/applications.py:1070-1103）。

4. **可扩展性**：文档

问：参数校验的元数据是怎么定义的
  预期找到 / 实际找到 -> 符合预期
  LLM 调用 1 次，检索 12 片段，最近距离 0.4301

  答：根据现有片段，参数校验的元数据是通过 `Header`（fastapi/param_functions.py:813-932）中一系列 `Annotated[...]` 字段配合 `Doc(...)` 说明来定义的，包括：

- `le`：数值必须小于等于该值
- `min_length` / `max_length`：字符串的最小/最大长度
- `pattern`：字符串校验的正则表达式（`regex` 已废弃，改用 `pattern`）
- `discriminator`：用于区分 tagged union 类型的字段名
- `strict`：是否启用严格校验
- `multiple_of`：数值必须是该值的倍数
- `allow_inf_nan`：是否允许 `inf`、`-inf`、`nan`
- `max_digits` / `decimal_places`：decimal 类型的最大位数/小数位数
- `examples` / `example`（已废弃）/ `openapi_examples`：用于声明示例值，会体现在生成的 OpenAPI 文档中

这些元数据项都以 `Annotated[类型, Doc("说明")] = 默认值` 的形式定义在fastapi/param_functions.py:813-932 所示的函数参数签名中，用来描述每个校验参数的类型、含义及默认值。

其余片段（LabelSettings、JsonApiError、test_openapi_schema 等）与参数校验元数据定义无直接关联，未涉及该问题的具体内容。
