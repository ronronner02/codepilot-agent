────────────────────────────────────────────────────────────────────
三、镜像内无 API key
────────────────────────────────────────────────────────────────────

设计（两重保证）
  backend/Dockerfile 不 COPY .env
  .dockerignore 排除 .env 与 .env.*（但保留 !.env.example）
  compose 用 env_file 在运行时注入

实测核实（此前只有设计推断）
  后端镜像
    env | grep -iE "key|token|secret"
      → 只有 GPG_KEY=7169605F...（python 基础镜像的公开签名密钥，非项目密钥）
      → 无 DEEPSEEK_API_KEY、无 EMBEDDING_API_KEY
    ls -a /app | grep "^\.env"           → 无 .env
    ls /app                               → backend、pyproject.toml（仅此两项）
    docker history --no-trunc | grep -c "sk-"        → 0
    grep -rlE "sk-[A-Za-z0-9]{20,}" /app | wc -l    → 0
  前端镜像
    env | grep -iE "key|token|secret"     → 空
    docker history 中 1 处 ".env" 匹配 → 经查是 nginx 基础镜像自带的
      15-local-resolvers.envsh 文件名误命中，非密钥

运行时注入确认（反向验证：镜像里没有，运行时必须有）
  容器内 printenv：
    DEEPSEEK_API_KEY  set=yes len=51
    EMBEDDING_API_KEY set=yes len=51
  设计成立：密钥不进镜像层，运行时由 env_file 注入。

本次核查刻意避开了 backlog 首条记录的泄露动作
  compose 配置核对改为只提取结构（services、卷挂载目标、端口、environment 的
  键名），全程不打印任何变量值。
    docker compose config → exit 0
    services: backend, frontend
    卷挂载目标: /data
    端口: 8000, 80
    WORKSPACE_ROOT: /data  ✓（与 U9 的缓存落盘路径对齐）
